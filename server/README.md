# AG VPS Unlock — серверная часть (VPS relay)

Серверная часть релея: knock-демон `agvpsd` (UDP 1604), CLI для управления
токенами и установщик systemd-службы. Только стандартная библиотека
Python 3.9+, без сторонних зависимостей.

## Состав

| Файл | Назначение |
|------|------------|
| `agvpsd.py` | knock-демон: слушает UDP :1604, проверяет токены, ведёт allow-лист |
| `agvps-token.sh` | CLI администратора: токены, lock, allow-лист |
| `setup-vps.sh` | установщик: копирует файлы, включает systemd-службу |
| `agvpsd.service` | unit-файл systemd |

Требования: Ubuntu/Debian с systemd, python3, root.

## Установка

```bash
scp -r server/ root@<VPS_IP>:/root/agvps
ssh root@<VPS_IP>
cd /root/agvps
sudo ./setup-vps.sh
```

Установщик скопирует демона в `/usr/local/bin/agvpsd.py`, unit — в
`/etc/systemd/system/agvpsd.service`, выполнит `daemon-reload` и
`enable --now`. Правила firewall при установке **не изменяются**:
если ufw активен, откройте порт вручную:

```bash
sudo ufw allow 1604/udp
```

## Токены: полный цикл

```bash
sudo agvps-token.sh add my-laptop   # создать токен, секрет показывается сразу
sudo agvps-token.sh copy my-laptop  # вывести только секрет + подсказка
```

Секрет вставляется в приложение AgVpsUnlock на Windows: поле «Токен» →
«Сохранить» → «Проверить сервер». При первом же успешном knock IP клиента
попадает в allow-лист автоматически.

Команды CLI:

| Команда | Действие |
|---------|----------|
| `add <имя>` | создать токен клиента |
| `list` | таблица всех токенов, **включая полные секреты** |
| `show <имя>` | напечатать только секрет |
| `copy <имя>` | как `show`, плюс подсказка по передаче |
| `revoke <имя>` | отозвать токен (вступает в силу в течение секунды) |
| `lock on\|off\|status` | блокировка tcp/443 по allow-листу |
| `allow list` / `allow remove <ip>` | просмотр/чистка allow-листа |

Ротация токена = `revoke` старого + `add` нового.

## Совместимость с ботом подписок (legacy)

Если на сервере уже работает автоматика, которая ведёт свой файл секретов
(например `/opt/agvps/tokens`, пополняемый Telegram-ботом), установщик
обнаружит его и пропишет в unit-файл:

```
Environment=AGVPS_LEGACY_TOKENS=/opt/agvps/tokens
```

Демон принимает такие секреты **наравне** с `state.json` (перечитывает
файл по mtime), поэтому бот продолжает выдавать токены без изменений.
Просмотреть их: `sudo agvps-token.sh legacy-list` — только чтение;
отзыв выполняется средствами той системы, которая файлом владеет.

## Блокировка firewall (опционально)

По умолчанию **выключена**. Текущее состояние: `agvps-token.sh lock status`.

При `lock on` демон ограничивает входящий tcp/443 адресами из allow-листа
(nftables, при отсутствии — iptables). Принципы:

- используются только собственная таблица `inet agvps` / цепочки
  `AGVPS`, `AGVPS6` — существующие правила никогда не сбрасываются;
- любая ошибка применения откатывает изменения agvps;
- при остановке службы правила agvps снимаются;
- новый клиент разблокирует себя сам: knock добавляет его IP в allow-лист.

Включение:

```bash
sudo agvps-token.sh lock on
```

Осторожно: до первого knock клиента его доступ к 443 будет закрыт.
Если nft/iptables отсутствуют, блокировка не работает (видно в журнале).

## Протокол knock

Пакет — ровно 26 байт UDP:

```
байты 0-1    ASCII "AG"
байты 2-9    uint64 BIG-ENDIAN unix-время (секунды)
байты 10-25  первые 16 байт HMAC-SHA256(key=UTF8(token),
                                        msg=UTF8("agvps|" + str(ts)))
```

- окно валидности: |время сервера − ts| ≤ 300 секунд;
- перебираются все неотозванные токены, сравнение константное
  (`hmac.compare_digest`);
- валидный knock → ответ `K` **из того же сокета**, IP добавляется в
  allow как /32 (IPv6 — /128);
- неверный формат/HMAC/метка времени → ответ `X`, не чаще 5 раз в секунду
  на источник (защита от брутфорса).

Часы клиента и сервера должны расходиться не более чем на 5 минут
(NTP на VPS решает это по умолчанию).

## Файл состояния

`/etc/agvps/state.json` (каталог 700, файл 600, запись атомарная):

```json
{
  "tokens": [
    {"name": "my-laptop", "secret": "...", "created": 1750000000,
     "revoked": false, "last_used": null, "last_ip": null}
  ],
  "allow": ["1.2.3.4/32"],
  "lock": false
}
```

Демон подхватывает правки файла (revoke, lock, allow) в течение секунды.

## Безопасность

- Секреты никогда не пишутся в журнал: лог содержит только имя, IP и
  результат (ok/bad).
- Файл состояния 600, каталог 700; CLI работает только под root.
- Сравнение HMAC — константное; перебор ответов ограничен rate-limit'ом.
- Порт и пути настраиваются переменными окружения `AGVPS_PORT`,
  `AGVPS_STATE`, `AGVPS_LOCK`.

## Диагностика

```bash
journalctl -u agvpsd -f          # живой лог демона
systemctl status agvpsd          # состояние службы
ss -lunp | grep 1604             # слушается ли порт
sudo agvps-token.sh list         # кто и когда стучался
```

Удаление службы: `sudo systemctl disable --now agvpsd && sudo rm
/usr/local/bin/agvpsd.py /etc/systemd/system/agvpsd.service && sudo
systemctl daemon-reload`.
